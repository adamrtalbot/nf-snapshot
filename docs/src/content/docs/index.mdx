nf-snapshot checks the files a Nextflow run publishes against a JSON snapshot committed to your pipeline repository. If a file is missing, changed, or unexpected, the run exits with status `1`.

## Configure once. Check every run.

Load the plugin at the top level of `nextflow.config`, then enable it in a test profile:

```groovy title="nextflow.config"
plugins { id 'nf-snapshot@0.1.0' }

profiles {
    test_full {
        snapshot {
            enabled = true // [!annotate] The plugin stays inactive in other profiles.
            file = 'tests/snapshots/test_full.json'
        }
    }
}
```

Create a baseline, review and commit it, then run the same profile to check future outputs:

```bash
NXF_SNAPSHOT_UPDATE=true nextflow run . -profile test_full
nextflow run . -profile test_full
```

For an unreleased version, install the plugin locally first; see <a href={`${import.meta.env.BASE_URL}getting-started/`}>Getting started</a>.

## See what changed

```text title="A snapshot mismatch"
nf-snapshot: outputs differ from /path/to/tests/snapshots/test_full.json
  missing:    salmon/sample2/quant.sf
  changed:    multiqc/multiqc_data/multiqc_general_stats.txt
  unexpected: salmon/sample3/quant.sf
```

Only files published by the current run are captured, through `publishDir` or workflow outputs. Compressed `.gz` files are compared after decompression, and published directories are expanded into their files.
